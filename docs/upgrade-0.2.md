# Upgrading to 0.2.0

`CHANGELOG.md` is generated by release-please from commit messages. This page collects the behaviour changes a 0.1.0 project sees, and the steps to take.

## Steps

1. Upgrade the package and run `lb-contracts gen` once. There is no `contracts.lock.json` yet, so every schema counts as new: the run passes and creates the file at the project root.
2. Commit `contracts.lock.json`. From now on `lb-contracts gen` and `lb-contracts validate` gate every schema edit against it (see [cli.md § Breaking-change gate](./cli.md#breaking-change-gate)).
3. Delete `.loopback/cache/diff-state.json` if it exists; 0.2.0 no longer reads it.
4. If a consumer destructures or indexes a fixed-length array type from a `.types.ts` sidecar as a tuple, switch it to array access (see below).
5. If you `switch` exhaustively over `KnownEmitterKind`, add a `'mongodb'` case.

## Breaking changes (0.x)

- **Stage 6 runs on every `gen` and `validate`.** 0.1.0 compared schemas only when a source version pin changed. 0.2.0 compares every loaded schema with its last accepted form in `contracts.lock.json` and refuses a breaking edit (a property removed or newly required, an enum value removed, a type or bound tightened, ...) unless `--allow-breaking` is passed or `migration-strategy.<schemaId>.mode` is `'allow'`. Removing a schema, or renaming its `$id`, is breaking. `validate` never writes the lock; a successful `gen` advances it.
- **Remote-source schemas are recorded by digest.** Schemas from `npm:`, `git+`, `https://` or plugin sources appear in the lock only as `$id` plus a `sha256-` digest, so private contract content is not copied into your repository. Any change to one (for example after a version-pin bump) needs `--allow-breaking` once. Set `"baseline": {"includeRemote": true}` to store and classify their full bodies instead, or `"baseline": {"enabled": false}` to turn the gate off.
- **Stage 4 validates JSON Pointer fragments.** A `$ref` such as `#/$defs/missing` or `money#/$defs/nope` that points at nothing now fails `gen` / `validate`; 0.1.0 left it to Ajv, which only noticed if the fragment was reached. Plain `$id`s (`money`, `customer.v1`) and their fragments now resolve in stage 4; 0.1.0 rejected them as invalid URI references.
- **Fixed-length arrays type as `T[]`.** The types emitter renders an array whose `minItems` equals `maxItems` as `T[]` instead of a tuple such as `[string, string]`. The bounds stay in the JSDoc and in the Zod / Ajv validators.
- **Canonical type alias.** When a `.types.ts` file's root type is named from `title` rather than the `$id` (`Customer` for `customer.v1`), the file also exports `export type CustomerV1 = Customer;`. Other schemas import this canonical name.
- **`KnownEmitterKind` includes `'mongodb'`.** A new experimental `--emit-mongodb` sidecar writes MongoDB `$jsonSchema` validators.

## Other changes worth knowing

- URL and URN `$id`s now produce valid identifiers and file slugs in every emitter; plain-id output is byte-identical to 0.1.0. When two URL / URN ids would share a file or type name, the names are qualified deterministically (host, then path words, then a short hash of the `$id`); see [emitters.md § Naming and collisions](./emitters.md#naming-and-collisions). A plain id never changes name.
- `gen --out-dir <dir>` and the `outputDir` config key move model-scoped output. The directory must be inside the project, outside `node_modules`, `.git`, `_meta`, `.loopback` and the schemas / configs directories.
- `.loopback/cache/` is no longer written by stage 6.
- `_meta/loopback-config.schema.json` gains `outputDir`, `baseline` and `emit.mongodb`.
